# Module 2 – Authentication and Credential Management

This outline defines the authentication and credential-management knowledge assessed in Module 2.

## 2.1 Authentication foundations

- The distinction among identification, identity proofing, authentication, and authorization
- Digital identities, identifiers, credentials, authenticators, and authentication factors
- Human identities and non-human identities, including applications, services, devices, and automated jobs
- Authentication methods selected according to the identity, application context, threats, and required assurance
- Common authentication methods, including passwords, one-time codes or links, passkeys, API keys, certificates, and federated login
- Knowledge, possession, and biometric factors: something a person knows, has, or is
- The requirement for multi-factor authentication (MFA) to use factors from different categories
- Consistent authentication across every path to protected functionality
- The security benefits of established identity services and framework authentication features

## 2.2 Credential and authenticator lifecycle

- Enrollment and provisioning that bind an authenticator to the intended identity
- Secure delivery, storage, transmission, replacement, recovery, revocation, and retirement of credentials
- Password length, breached-password screening, password-manager support, and evidence-based change policies
- Password storage using an appropriate password-hashing algorithm, a unique salt, and a suitable work factor
- The purpose and storage requirements of an optional password pepper
- Protection of credentials from source code, client-side storage, URLs, logs, and other unintended exposure
- Short-lived or dynamically issued credentials in preference to long-lived shared secrets
- Ownership, purpose, scope, expiration, and revocation for non-human credentials
- API keys, client secrets, service-account credentials, client certificates, and managed workload identities
- Mutual Transport Layer Security (mTLS) as certificate-based client and server authentication
- Authentication secrets contained in configuration values such as database connection strings
- Default, hard-coded, shared, orphaned, and excessively privileged credentials as common weaknesses

## 2.3 Multi-factor and passwordless authentication

- Passwords and personal identification numbers as knowledge factors
- One-time-password devices, authenticator applications, security keys, and client certificates as possession factors
- Biometrics as inherence factors and their common role in activating a local authenticator
- Security and usability differences among SMS codes, time-based one-time passwords, push approval, backup codes, security keys, and passkeys
- Phishing resistance and origin binding in FIDO2 and Web Authentication (WebAuthn)
- Enrollment, replacement, reset, recovery, and fallback paths as part of the authentication design
- Re-authentication and step-up authentication for sensitive changes and operations
- Authentication fatigue, real-time phishing, stolen recovery codes, and other ways to bypass weaker factors

## 2.4 Session management

- The relationship among authentication, a session token, and authorization decisions on later requests
- Reference tokens and self-contained tokens as ways to represent a session
- Session identifiers generated with sufficient entropy and accepted only by a trusted application component
- Protection of session tokens during transport and storage
- Cookie attributes, including `Secure`, `HttpOnly`, and `SameSite`, and restricted cookie scope
- The relationship between automatically submitted cookies, `SameSite`, and cross-site request forgery defenses
- Session renewal after authentication, re-authentication, and privilege changes
- Idle timeouts, absolute lifetimes, concurrent-session policy, and risk-based re-authentication
- Server-side session termination during logout, account disablement, credential compromise, and expiration
- Revocation considerations for self-contained session tokens
- Session fixation, hijacking, theft, replay, and unintended disclosure

## 2.5 Federation, single sign-on (SSO), and tokens

- SSO as a user experience and federation as a trust relationship between security domains
- The roles of an identity provider and relying party in federated authentication
- OAuth 2.0 as an authorization framework and OpenID Connect (OIDC) as an identity layer built on OAuth 2.0
- Security Assertion Markup Language (SAML) assertions as a common form of federated authentication
- Authorization Code flow protections, including exact redirect URI validation, `state`, `nonce`, and Proof Key for Code Exchange (PKCE)
- Established protocol libraries and trusted configuration instead of custom protocol implementations
- JSON Web Token (JWT) structure and the distinction between signing and encryption
- The distinction among ID tokens, access tokens, refresh tokens, and session tokens
- Token and assertion validation for integrity, algorithm, trusted key source, issuer, audience, purpose, and validity period
- Sensitive information and unnecessary claims in readable token payloads
- Coordinated session lifetime, re-authentication, and logout across an application and its identity provider

## 2.6 Authentication failures and testing

- Brute-force attacks, password spraying, credential stuffing, and authentication fatigue
- Account enumeration through response content, status, timing, and recovery behavior
- Authentication bypass through alternate endpoints, methods, protocols, or recovery paths
- Missing, weak, default, expired, revoked, replayed, or incorrectly scoped credentials
- Positive tests for supported authentication and session flows
- Negative tests for invalid, tampered, expired, revoked, replayed, and incorrectly scoped authentication artifacts
- Tests for password reset, authenticator enrollment and recovery, session renewal and termination, and federated login
- Tests for rate limiting, generic responses, session fixation, token disclosure, and inconsistent authentication paths
- Regression coverage for authentication controls and failure handling
